# План реализации веб-приложения `salary`

Документ опирается на требования из [PRD_SPEC.md](./PRD_SPEC.md) и визуальную спецификацию из [design.md](./design.md).

> **Примечание:** Перед началом **Фазы 3 (Дизайн-система и UI)** файл [design.md](./design.md) должен быть заполнен вашими данными по дизайну. Фазы 0–2 (инфраструктура, БД Turso, авторизация) можно реализовывать параллельно или сразу после утверждения плана.

---

## Обзор этапов

| Фаза | Название | Ключевой результат |
|---|---|---|
| **Фаза 0** | Инициализация проекта | Настроенный Next.js (App Router, TS, Tailwind), структура папок, `.env.example` |
| **Фаза 1** | База данных Turso + Drizzle | Схема БД, миграции, клиент Turso, сидирование базовых категорий |
| **Фаза 2** | Авторизация (Better Auth) | Регистрация, вход, выход, защита маршрутов, изоляция пользователей |
| **Фаза 3** | Дизайн-система из `design.md` | Токены, шрифты, цвета, базовые UI-компоненты, App Shell (навигация) |
| **Фаза 4** | Категории доходов и расходов | Страница `/categories`, полный CRUD, цвета/иконки, мягкая архивация |
| **Фаза 5** | Транзакции (доходы и расходы) | Страница `/transactions`, форма добавления/редактирования, фильтры, поиск, пагинация |
| **Фаза 6** | Дашборд и аналитика | Страница `/dashboard`, KPI-карточки, графики по категориям и динамике, выбор периода |
| **Фаза 7** | Настройки, тестирование и деплой | Страница `/settings`, тесты, проверка безопасности, деплой на Vercel + Turso Cloud |

## Фаза 0: Инициализация и каркас проекта

**Цель:** развернуть чистый проект Next.js и подготовить базовые инструменты разработки.

- [ ] Создать проект Next.js (App Router, TypeScript, Tailwind CSS, ESLint, `src/`).
- [ ] Установить зависимости:
  - БД: `@libsql/client`, `drizzle-orm`, `drizzle-kit` (dev)
  - Авторизация: `better-auth`
  - Валидация и утилиты: `zod`, `lucide-react` (или иконки из `design.md`), `clsx`, `tailwind-merge`
  - Графики: `recharts` (при необходимости скорректировать по `design.md`)
- [ ] Создать `.env.example` и локальный `.env.local` (по умолчанию `TURSO_DATABASE_URL="file:./local.db"` для локальной разработки).
- [ ] Настроить структуру каталогов (`src/db`, `src/lib`, `src/actions`, `src/components`, `src/app/(auth)`, `src/app/(app)`).
- [ ] Добавить вспомогательный модуль `src/lib/money.ts` (перевод сумм `major <-> minor`, форматирование валюты с `Intl.NumberFormat`).

**Критерий готовности:** `npm run dev` запускается без ошибок, `npm run lint` и `tsc --noEmit` проходят чисто.

## Фаза 1: База данных Turso и Drizzle ORM

**Цель:** описать схему данных, настроить подключение к Turso и механизм миграций.

- [ ] Настроить `src/db/index.ts` с `createClient` из `@libsql/client` и обёрткой `drizzle(client, { schema })`.
- [ ] Настроить `drizzle.config.ts` с диалектом `turso` / `sqlite` и чтением `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`.
- [ ] Описать таблицы в `src/db/schema.ts`:
  - `users` (включая поле `currency`, по умолчанию `'RUB'`), `sessions`, `accounts`, `verifications`;
  - `categories` (`id`, `user_id`, `name`, `type`, `color`, `icon`, `is_archived`, timestamps + уникальный индекс);
  - `transactions` (`id`, `user_id`, `category_id`, `type`, `amount_minor`, `description`, `occurred_at`, timestamps + композитные индексы).
- [ ] Добавить npm-скрипты: `db:generate`, `db:migrate`, `db:push`, `db:studio`.
- [ ] Реализовать `src/db/seed-defaults.ts` — идемпотентную функцию создания стартовых категорий доходов и расходов для нового `userId`.
- [ ] Применить первую миграцию к локальной БД (`file:./local.db`) и проверить создание таблиц и индексов.

**Критерий готовности:** миграции применяются без ошибок; схема поддерживает работу как с локальным SQLite, так и с удалённым Turso Cloud.

## Фаза 2: Авторизация и защита доступа

**Цель:** реализовать безопасную регистрацию, вход, выход и изоляцию данных пользователей.

- [ ] Настроить `src/lib/auth.ts` (Better Auth + `drizzleAdapter` для SQLite + `emailAndPassword: { enabled: true }`).
- [ ] Подключить хук создания пользователя (`databaseHooks.user.create.after`) для автоматического вызова `seedDefaultCategories(user.id)`.
- [ ] Создать Route Handler `src/app/api/auth/[...all]/route.ts`.
- [ ] Настроить клиент `src/lib/auth-client.ts`.
- [ ] Создать хелпер `requireUser()` для серверных компонентов и Server Actions (возвращает текущего пользователя или редиректит на `/login`).
- [ ] Настроить `src/middleware.ts` (или серверную проверку в `src/app/(app)/layout.tsx`) для защиты приватных маршрутов и редиректа авторизованных со страниц `/login` и `/register`.
- [ ] Реализовать страницы `/login` и `/register` с Zod-валидацией и отображением ошибок.

**Критерий готовности:** можно зарегистрировать двух пользователей, войти/выйти; при регистрации автоматически создаются базовые категории; неавторизованный доступ к `/dashboard` перенаправляет на `/login`.

## Фаза 3: Дизайн-система (из `design.md`) и App Shell

**Цель:** перенести визуальную спецификацию из [design.md](./design.md) в код и собрать единый каркас приложения.

- [ ] Прочитать заполненный `design.md` и настроить CSS-переменные / тему Tailwind в `src/app/globals.css` (палитра, семантические цвета доходов/расходов, шрифты, радиусы, тени, светлая/тёмная тема).
- [ ] Подключить выбранные шрифты через `next/font`.
- [ ] Собрать базовые переиспользуемые UI-компоненты в `src/components/ui/` (Button, Input, Select, Card, Modal/Drawer, Badge, Tabs, EmptyState, Skeleton, Toast).
- [ ] Собрать `src/app/(app)/layout.tsx` (боковая панель на десктопе, адаптивная навигация на мобильных, шапка с профилем и кнопкой выхода).
- [ ] Оформить экраны `/login` и `/register` в едином стиле из `design.md`.

**Критерий готовности:** все базовые элементы и навигация полностью соответствуют `design.md` на десктопе и мобильных устройствах.

## Фаза 4: Категории доходов и расходов (`/categories`)

**Цель:** дать пользователю полный контроль над категориями.

- [ ] Написать Zod-схемы в `src/lib/validators/category.ts`.
- [ ] Реализовать Server Actions в `src/actions/categories.ts`:
  - `createCategory` (проверка дубликатов по `(user_id, type, name)`);
  - `updateCategory` (смена названия, цвета, иконки);
  - `deleteOrArchiveCategory` (проверка наличия связанных транзакций: удаление если 0, иначе `is_archived = 1`);
  - `restoreCategory` (возврат из архива).
- [ ] Реализовать страницу `/categories`:
  - Вкладки / секции «Расходы» и «Доходы»;
  - Отображение количества операций по категории;
  - Модальное окно / форма создания и редактирования (выбор цвета из палитры и иконки);
  - Переключатель «Показать архивные» с возможностью восстановления.

**Критерий готовности:** CRUD категорий работает для обоих типов; удаление категории с операциями безопасно переводит её в архив без потери данных.

---

## Фаза 5: Транзакции — доходы и расходы (`/transactions`)

**Цель:** реализовать удобный учёт и поиск всех финансовых операций.

- [ ] Написать Zod-схемы в `src/lib/validators/transaction.ts`.
- [ ] Реализовать Server Actions в `src/actions/transactions.ts`:
  - `createTransaction` (конвертация суммы в `amount_minor`, проверка принадлежности категории пользователю и совпадения `category.type === type`);
  - `updateTransaction`;
  - `deleteTransaction`.
- [ ] Реализовать серверный запрос выборки с фильтрами (`from`, `to`, `type`, `categoryId`, `search`, `page`, `pageSize`) и синхронизацией фильтров с URL Search Params.
- [ ] Реализовать UI страницы `/transactions`:
  - Панель фильтров (период, тип, категория, поиск);
  - Список / таблица операций с цветовой индикацией дохода/расхода, иконкой категории, датой и суммой (`tabular-nums`);
  - Модалка / форма создания и редактирования операции (динамическая подстановка категорий под выбранный тип, быстрый выбор даты);
  - Диалог подтверждения удаления;
  - Пагинация и пустые состояния.

**Критерий готовности:** все операции CRUD работают корректно, фильтры и пагинация сохраняются в URL, невозможно создать операцию с чужой или несовместимой категорией.

## Фаза 6: Дашборд и аналитика (`/dashboard`)

**Цель:** показать пользователю полную картину доходов, расходов и баланса за период.

- [ ] Реализовать оптимизированные SQL-запросы в `src/db/queries/analytics.ts`:
  - Итоги за выбранный период (`income`, `expense`, `net`) + общий баланс за всё время;
  - Разбивка по категориям (`GROUP BY category_id`, процент от общей суммы);
  - Временной ряд доходов и расходов (по дням или по месяцам в зависимости от длины периода);
  - Последние N транзакций.
- [ ] Реализовать UI страницы `/dashboard`:
  - Переключатель периода (текущий месяц, прошлый месяц, стрелки `← / →`, произвольный диапазон);
  - 4 KPI-карточки;
  - График структуры расходов / доходов по категориям (Donut/Bar + легенда);
  - График динамики доходов vs расходов;
  - Виджет последних операций + кнопка быстрого добавления транзакции.

**Критерий готовности:** суммы на дашборде математически совпадают с реестром транзакций; графики корректно отображают пустые периоды и адаптируются под мобильные экраны.

## Фаза 7: Настройки, проверка качества и деплой

**Цель:** довести приложение до продакшн-готовности и подключить облачную БД Turso.

- [ ] Реализовать страницу `/settings`:
  - Редактирование имени и выбор валюты по умолчанию;
  - Смена пароля / завершение сессий.
- [ ] Написать тесты (Vitest):
  - Юнит-тесты для `src/lib/money.ts` (форматирование и округление `major <-> minor`);
  - Тесты Zod-валидаторов;
  - Проверка бизнес-логики (архивация категории с транзакциями, несовпадение типов, изоляция пользователей).
- [ ] Провести финальную проверку:
  - `npm run lint`, `npm run build`, ручной проход всех пользовательских сценариев (Desktop + Mobile);
  - Проверка соответствия `design.md`.
- [ ] Подготовка к продакшну (Turso Cloud + Vercel):
  - Создать БД в Turso (`turso db create salary`), получить `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`;
  - Применить миграции к облачной БД (`npm run db:migrate`);
  - Настроить переменные окружения на хостинге и выполнить деплой.

**Критерий готовности:** приложение развёрнуто, подключено к Turso Cloud, все критерии приёмки из `PRD_SPEC.md` выполнены.
